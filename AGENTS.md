# IOMETE Documentation

Docusaurus 3 site (MDX v3) for the IOMETE platform docs. `CLAUDE.md` is a symlink to this file — edit only `AGENTS.md`.

## Setup

```bash
npm ci           # first, always
npm run start    # dev server at http://localhost:3000/resources/
npm run build    # production build into build/
```

Fresh worktrees have no `node_modules` (~1.3G once installed; `build/` adds ~216M, both gitignored). Skip `npm ci` and both scripts fail with `sh: docusaurus: command not found`, exit 127. The build is slow, so redirect and grep it: `npm run build > /tmp/build.log 2>&1`. A clean tree builds with no `[WARNING]` lines at all, so every warning you see is yours. `devbox.json` pins `nodejs@18`, but newer Node builds fine. CI installs with yarn (see CI below), so never let a run rewrite either lockfile as a side effect.

## Authoring

- MDX v3: comment with `{/* */}`, never `<!-- -->`. A bare `{name}` in prose breaks the build — write `\{name\}` or backtick it.
- Images: `<Img>` from `@site/src/components/Img`, not `![]()`. Ship a `-dark.png` variant for dark mode. Props: `internal_docs/img-component.md`.
- Screenshots: crop to what you are showing (the sidebar, not the whole screen) and aim for under 100KB per image. Reviewers ask about both.
- Compressing: `TINYPNG_API_KEY=<key> node scripts/tinypng-compress.mjs <paths>`, or `--list files.txt`. Largest first, leaves a file untouched unless it shrinks by 5%, and prints the month's running count — the free key is 500 compressions/month for everyone, so never re-run it over already-committed images. Key setup, the `tinypng-cli` alternative and resize flags: `internal_docs/img-component.md`.
- Frontmatter: `title`, `description`, `sidebar_label`, `last_update.date`, `last_update.author`. Glossary entries are the exception: `title`, `description`, `banner_description`, `alphabet`, with no `sidebar_label` and no `last_update`.
- Prose: second person, active voice, present tense, Title Case headings, gerunds for tasks ("Creating a Cluster").
- Links: relative file paths (`./feature.md`, `../category/page.md`); never prefix `/docs/`. The target's `slug` is honoured automatically. Fix a link the build rejects; never silence one with `pathname://`.
- Release notes: `RELEASE_NOTES_GUIDELINES.md`. Porting from Confluence: `internal_docs/confluence-conversion-guide.md`.

## Routing

`baseUrl` is `/resources/` (`docusaurus.config.js`), not `/`. Every URL needs that prefix.

| Content dir | Serves at |
| -- | -- |
| `user-guide/` | `/resources/user-guide/<path>` |
| `docs/` | `/resources/<path>` — the `docs/` segment is dropped |
| `blog/` | `/resources/blog/<path>` |
| `glossary/` | `/resources/glossary/<path>` |

A frontmatter `slug` is relative to its own plugin's `routeBasePath`, not the site root: `user-guide/iam/admin-roles.md` with `slug: /admin-roles` serves at `/resources/user-guide/admin-roles`.

## Verifying a Page

The dev server is client-rendered: every path returns the same ~2KB SPA shell with HTTP 200, including paths that do not exist. `curl | grep` proves nothing there. Use instead:

- Route registered? `grep "path: '/resources/<route>'" .docusaurus/routes.js` (generated by a run).
- Content or rendered `href` right? `npm run build`, then read `build/<route-minus-baseUrl>/index.html`.

## CI

All in `.github/workflows/`.

| Workflow | Runs on | What it proves |
| -- | -- | -- |
| `build-check.yaml` | every PR to `main` | the site builds, so every route, relative `.md` link and `#anchor` resolves |
| `snapshot-gate.yaml` | PRs touching only `package.json` / `yarn.lock` | a dependency bump leaves the built HTML unchanged. Never mix content and dependency changes in one PR, or the gate skips itself and the bump ships unvalidated |
| `deployment_v3.yaml` | `workflow_dispatch` only | nothing automatic. Merging does not publish, so run this workflow to sync `build/` to S3 |

## Gotchas

- Anchors are opt-in, not scraped from the rendered page: only markdown headings, list items and `<details id="...">` register one. A raw `<h2 id="x">` in MDX registers nothing, so `#x` fails the build even though the page renders fine. Use a heading or `<details id="...">`.
